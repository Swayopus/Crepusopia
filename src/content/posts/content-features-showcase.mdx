这篇文章既介绍新增的正文能力，也用自己演示它们。写作时仍然优先使用普通 Markdown；只有标签页需要 MDX，其余效果都可以直接写。

## 图片：图注与点击放大

![暮色中的层叠山峦与落日插画](/images/demo/content-features.svg)

普通图片语法不变：图注直接取 `alt` 文本，点击图片会打开灯箱，按 Esc 或点击遮罩关闭，关闭后焦点回到图片按钮。

## 脚注：把补充说明放到文末

正文先给出结论[^why]，需要时再查看细节[^detail]。脚注编号可以连续使用，也可以重复引用同一条。

[^why]: 脚注里可以继续写**行内格式**、`代码` 和[链接](https://example.com)。
[^detail]: 点击编号跳到文末，再点注释末尾的箭头回到原位置。手机吸顶栏不会挡住跳转目标。

## 代码：文件名、行号与重点行

在围栏信息里加上 `title`、`ln` 和行号范围，就能得到带标注的代码块。复制按钮仍然只复制代码本身，不包含行号。

```ts title="src/utils/greet.ts" ln {2,4-5}
export function greet(name: string) {
  const trimmed = name.trim();
  if (!trimmed) return "你好，陌生人";
  return `你好，${trimmed}`;
}
```

不需要标注时保持原来的写法即可，长代码块仍会自动折叠：

```js
const plain = "没有额外元数据，就维持普通代码块的样式";
console.log(plain);
```

写法速查：

````md
```ts title="src/utils/greet.ts" ln {2,4-5}
// 代码
```
````

- `title="..."` 或 `filename="..."`：显示文件名；
- `ln`：显示行号；
- `{2,4-5}`：标记重点行，行号从 1 开始。

## 折叠补充内容

不是提示块、但又不想一直占篇幅的推导或补充，可以放进原生折叠区，键盘和读屏都能直接操作。

<details>
<summary>查看完整推导</summary>

折叠区内部照常写 Markdown：

- 列表、**强调**和 `行内代码`
- 行内公式 $e^{i\pi}+1=0$
- 任意链接与图片

</details>

## 手机上的宽表格

下面这张表在窄屏上只让表格区域左右滑动，正文宽度保持不变。

| 环境 | 启动命令 | 构建命令 | 预览方式 | 适合的场景 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 本地开发 | `npm run dev` | 自动按需编译 | 开发服务器热更新 | 写作与调样式 | 修改后无需手动构建 |
| 本地预览 | `npm run preview` | 需要先执行构建 | 读取 `dist/` 的静态服务 | 检查最终产物 | 改源码后要重新构建 |
| 持续集成 | `npm run build` | 完整构建与搜索索引 | 交给托管平台 | 发布前验证 | 与 `verify` 的前半段一致 |
| 完整检查 | `npm run verify` | 格式、类型、测试、构建 | 不启动服务 | 提交前自查 | 耗时最长但覆盖最全 |

## 写作语法速查

| 能力 | 写法 | 是否必须用 MDX |
| --- | --- | --- |
| 图注与放大 | `![图注](/images/example.png)` | 否 |
| 脚注 | `文字[^1]`，文末写 `[^1]: 注释` | 否 |
| 代码标注 | 围栏后写 `title="..." ln {1,3-4}` | 否 |
| 折叠区 | `<details><summary>标题</summary>正文</details>` | 建议 |
| 标签页 | 引入 `Tabs` 与 `Tab` 组件 | 是 |
| 宽表格 | 普通 Markdown 表格，自动加滚动容器 | 否 |

所有效果都限定在文章正文内，站点导航、目录、抽屉和字体不受影响。
